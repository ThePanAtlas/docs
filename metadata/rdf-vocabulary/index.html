    RDF vocabulary and SPARQL stores¶

    RDF is panAtlas's canonical graph form (owner decision 2026-09-26, recorded in GRAPH_STANDARDS.md). This page documents how the served property graph becomes RDF: the namespaces, classes and predicates, the named graph, the mapping rules, and the SPARQL stores that serve panAtlas together with mirrored external graphs. Code: web/rdf/build_rdf.py (export), web/rdf/qlever_build.py, qlever_serve.py, qlever_fold.py, qlever_export.py, nt_canon.py, sparql_client.py (stores), and web/acquisition/okn/ (mirrors).

    Item Status
    Export of the served graph to N-Quads Built (build_rdf.py)
    SPARQL store panatlas-okn (panAtlas + NSF OKN mirrors) Built and served inside the HPC cluster (vault, 2026-10-16)
    SPARQL store wikidata Built, held back in verification (vault, 2026-10-16)
    SPARQL store panatlas-restricted (licensed vocabularies, per-project access) Designed only (PLAN-restricted-data-umls.md)
    Public SPARQL endpoint None. The stores answer only inside the cluster network

    Namespaces¶

    Prefix IRI Use
    pa: https://panatlas.net/ontology# panAtlas classes and properties
    (nodes) https://panatlas.net/id/{id} One IRI per graph node; {id} is the node id, percent-encoded with no safe characters
    (statements) https://panatlas.net/id/edge%2F{edge id} Reified edges; the / after edge is percent-encoded because the whole string goes through the same encoder
    (graph) https://panatlas.net/graph/panatlas The named graph panAtlas curates
    (graph) https://purl.org/okn/frink/kg/{shortname} A mirrored NSF OKN graph
    (graph) http://www.wikidata.org/ The Wikidata mirror (source of record: Wikimedia)
    rdf: http://www.w3.org/1999/02/22-rdf-syntax-ns# rdf:type, reification, rdf:JSON literals
    rdfs: http://www.w3.org/2000/01/rdf-schema# rdfs:label, rdfs:Class, rdfs:subPropertyOf
    skos: http://www.w3.org/2004/02/skos/core# skos:Concept, skos:prefLabel, skos:exactMatch, skos:broader, skos:related
    dct: http://purl.org/dc/terms/ dct:description, dct:identifier, dct:title, dct:license, dct:publisher
    dcat: http://www.w3.org/ns/dcat# dcat:Dataset

    The MeSH stem is http, not https, because NLM mints http IRIs and only redirects https (vault project-panatlas, 2026-09-26). Site browser links in mesh_url stay https.

    Mapping rules (build_rdf.py)¶

    Inputs: the served graph (web/wp-plugin/panatlas-explorer/data/graph.json), the dataset registry (web/datasets.json) and web/codesystems.json. Optional: --okn-agents <dir> with each mirror agent's state.json, sor.json and provenance.json. Output: rdf/panatlas.nq and rdf/panatlas.stats.json. Every quad is in the named graph https://panatlas.net/graph/panatlas and is written once; repeats (for example wp_url and wiki_title naming the same page) are counted as duplicates_suppressed.

    Nodes¶

    Graph content RDF
    Every node <id> rdf:type pa:{Kind}, where {Kind} is the kind in upper camel case (llm-benchmark → pa:LlmBenchmark, fhir → pa:Fhir)
    Concept-like kinds: concept, disease, specialty, food, food-category, domain, capability, capability-group, eval-domain, gen-category, artifact-type, testing-type, register, training-stage, group, root, atlas-root Also rdf:type skos:Concept; label also as skos:prefLabel
    dataset Also rdf:type dcat:Dataset
    benchmark, llm-benchmark Also rdf:type dcat:Dataset and rdf:type pa:Benchmark
    model rdf:type pa:Model
    label rdfs:label
    desc dct:description
    Codes and links The table above
    Code-system nodes (onto-*) iri_stem, rdf_iri_basis and fhir_system are taken from codesystems.json, not from the graph, because the graph copy may predate an edit
    Any other field pa:{camelCase(field)}; a list of scalars repeats the predicate once per value

    Literal typing: booleans are xsd:boolean, integers xsd:integer, floats xsd:double; objects and lists of objects are serialised as sorted JSON with datatype rdf:JSON; strings are plain literals. Empty values (null, "", [], {}) are skipped, as are id, kind and label (already expressed).

    Kinds typed as skos:Concept

    training-stage, capability, testing-type and register nodes are typed skos:Concept because they are in the script's CONCEPT_KINDS. model, dataset, fhir, authority, codebase, system, guideline, kg, eval-suite, modality, measurement and method nodes are not. The last three are MeSH-grounded concepts whose kind is not in the list.

    Edges¶

    Every edge whose two ends exist becomes <from> pa:{camelCase(rel)} <to>. An edge with attributes is also reified:

    <https://panatlas.net/id/edge%2Fe-ca547f136f6d8d89b80f>
    a rdf:Statement ;
    rdf:subject   <https://panatlas.net/id/mesh-D000089323> ;
    rdf:predicate pa:partOf ;
    rdf:object    <https://panatlas.net/id/concept-geriatrics> ;
    pa:src        "mesh_tree" .

    The 36 relation predicates, with the number of triples at HEAD: pa:binds 15, pa:builtWith 14, pa:classifiedAs 1,756, pa:covers 3,607, pa:coversTopic 2,209, pa:defines 1, pa:derivedFrom 3, pa:evaluatedBy 2, pa:evaluatedOn 8, pa:executedOn 14, pa:follows 9, pa:groundedIn 239, pa:grounds 13, pa:groups 35, pa:hasArtifactType 816, pa:hasRegister 162, pa:hasResource 18, pa:hasTrainingStage 14, pa:hasType 21, pa:inCollection 83, pa:inDomain 97, pa:instantiates 36, pa:isType 106, pa:measuredOn 104, pa:partOf 5,430, pa:prereq 6, pa:related 44, pa:resolvesTo 251, pa:scored 85, pa:sftTrainedOn 2, pa:stageTrainedOn 45, pa:structuredAs 1,592, pa:testSetOf 14, pa:tests 247, pa:trainedOn 20, pa:uses 1. Their meaning is on Graph schema.

    The only alignment axioms asserted are:

    pa:partOf  rdfs:subPropertyOf skos:broader .
pa:related rdfs:subPropertyOf skos:related .

    Nothing else is asserted about the vocabulary. In particular there is no skos:narrower, no domain or range, and no class hierarchy.

    Dataset registry¶

    Each entry of datasets.json is written to <https://panatlas.net/id/dataset-{slug}>:

    Registry field RDF
    (entry) rdf:type dcat:Dataset
    urn dct:identifier
    name dct:title
    modality[] pa:modality
    license dct:license <IRI> when it is a URL, else pa:licenseStatement
    license_status, license_scope, status, role, host, access, used_in_training pa:licenseStatus, pa:licenseScope, pa:status, pa:role, pa:host, pa:access, pa:usedInTraining
    manifest.manifest_hash, manifest.file_count, manifest.total_bytes pa:manifestHash, pa:fileCount, pa:totalBytes
    maintained_externally pa:maintainedExternally true
    source_of_record.graph pa:sourceOfRecord <external graph IRI>, plus pa:agent, pa:upstreamVersion, pa:heldVersion, pa:upstreamLastUpdatedOn, pa:registryCommit
    (no external source of record) pa:sourceOfRecord <https://panatlas.net/graph/panatlas>

    Registry fields are documented on Dataset registry and Manifests.

    Named-graph descriptions¶

    With --okn-agents, each mirrored graph is described (not copied) inside the panAtlas graph:

    Triple Source
    <graph> rdf:type void:Dataset, prov:Entity always
    <graph> pa:mirroredBy <…/id/dataset-okn-{sn}> always
    <graph> pa:agent "okn-agent:{sn}" sor.json
    <graph> pav:version upstream version, provenance.json
    <graph> pa:heldVersion held version, state.json
    <graph> prov:generatedAtTime fetch time, state.json
    <graph> void:triples endpoint count, state.json
    <graph> void:sparqlEndpoint upstream endpoint, provenance.json
    <graph> dct:license, dct:publisher provenance.json
    <graph> pa:authoritativeNamespace <ns> (repeated) sor.json
    <graph> pa:authoritativeDeclared whether the publisher declared its namespaces or panAtlas inferred them

    The panAtlas graph describes itself as void:Dataset with dct:title "panAtlas (source of record: panAtlas)" and prov:generatedAtTime (the export time).

    Every pa: class used is declared rdf:type rdfs:Class with an rdfs:label, and every pa: property rdf:type rdf:Property with an rdfs:label.

    SPARQL stores¶

    panatlas-okn¶

    A read-only SPARQL 1.1 endpoint (QLever) holding panAtlas's own graph and every deployed NSF Open Knowledge Network graph that has been proven exact, each in the named graph of its source of record.

    Fact Value Source
    Build panatlas-okn-20261003T0039 web/rdf/README.md; vault reference-panatlas-sparql-endpoint
    Named graphs 44: panAtlas plus 43 OKN graphs same
    Triples 6,994,341,217 same; re-checked 2026-10-16
    Served 2026-10-03 to 2026-10-08 (Slurm job 226412), and since 2026-10-16 08:06 (job 237423) same
    Where A CPU-only Slurm job on a cluster compute node; reachable only inside the cluster network same
    Every graph Passed the exact round trip before the store went live (2026-10-03 07:43) vault

    The host and port change whenever a new build is switched live, so clients read them from the endpoint record stores/<name>.endpoint (host, port, url, job, started) under the store directory in <cluster project storage>/panatlas/qlever/. Queries run inside a Slurm job, never on a login node. A served query is stopped after one hour; whole-store scans take minutes.

    Agents query through the query_knowledge_graph tool of the Astral agent, which runs sparql_client.py over a forced-command key: parameters query, store (panatlas-okn or wikidata), describe=true (the named graphs with versions, sizes and proofs) and max_rows (at most 1,000); requests are base64 JSON ({"action": "describe", "store": …} or {"query": …, "store": …, "max_rows": …}); SPARQL Update is refused; timeout 120 s.

    wikidata¶

    A separate store from the Wikidata agent's md5-verified Wikimedia dump, in the named graph http://www.wikidata.org/. 21,350,107,674 triples, indexed 2026-10-02. It is held back: its first smoke test assumed English labels, but Wikidata stores a name shared by every language once under the language code mul (vault defect-wikidata-store-test-assumed-english-label). A verification rerun was submitted 2026-10-16 (job 237432). For English labels use FILTER(LANG(?l) IN ('en', 'mul')) and prefer en. The two stores are joined at query time with SERVICE.

    panatlas-restricted (designed)¶

    PLAN-restricted-data-umls.md designs a third QLever store for licensed vocabularies, never merged into panatlas-okn, with one named graph per source restriction level under https://panatlas.net/graph/restricted/…, panAtlas-derived relations in a separate derived graph, and per-user, per-project entitlements enforced in sparql_client.py (default deny, every call audited). Licensed content is internal and entitlement-gated; none of it enters the public graph or this documentation. At HEAD only acquisition (phase P1) has passed; the store is not built.

    Versioning and exactness¶

    Mirrors: one agent per graph¶

    Each OKN graph has its own agent (okn-agent:{shortname}, web/acquisition/okn/okn_agent.py) with its own state, provenance, source-of-record file, lock and update job. A six-hourly tick snapshots the OKN registry and VoID records (pav:version, lastUpdatedOn, void:triples per graph) and submits an independent sync job for each changed graph. Held copies live as raw/<sn>/<version>/part_*.nt with DONE and PROOF.json, and raw/<sn>/current points at the adopted version. A sync proves its new version and falls back to the previous one if any proof fails. Mirrored graphs are read-only and replaced wholesale; panAtlas never edits an externally maintained node or edge, it only links to it from its own graph.

    The source-of-record rule for nodes: a node IRI is maintained by whichever source's authoritative namespace covers it, by longest prefix (sor_index.json). Where a graph declares no namespaces, its own base IRI is taken as authoritative and marked inferred. An IRI no source claims belongs to its external authority (OBO, Wikidata, identifiers.org, NCBI).

    Proof levels (okn_prove.py, PROOF.json)¶

    Level Check
    fingerprint sha256 of the sorted distinct triples; per-predicate counts; blank-node count
    upstream Per-predicate counts equal the endpoint's; 20 random slices byte-identical at their offsets; 2,000 random triples byte-identical among the endpoint's objects for their subject and predicate
    reextract A second full extraction at page size 999,983 hashes identically
    store The triples exported back out of the local store equal the source (qlever_build.py)

    A graph is admitted to a store build only if its extraction verified and PROOF.json shows fingerprint, upstream and reextract ok.

    The store round trip¶

    A store is a query view, proven before it is served. qlever_build.py builds into stores/<name>-<stamp>/, then requires: every graph's triple count equals its verified count; no graph appears that was not admitted; the panAtlas MeSH joins hold; and the exact round trip passes. Only then does stores/<name> switch to the new build. A failed build writes stores/<name>.last_failure and is not resubmitted until fixed and re-verified.

    The round trip exports every graph back out of the store and requires that the sorted distinct non-blank triples of canon(export) hash identically to canon(fold(source)), that blank-node triple counts are equal (the store assigns its own labels), and that COUNT(*) equals the source's distinct stored values. nt_canon.py writes one spelling per RDF term; qlever_fold.py applies QLever's literal folding to the source. QLever cannot keep literals verbatim and has no setting to stop it (vault reference-qlever-literal-folding):

    Rule Effect
    integer xsd:integer becomes xsd:int (60-bit range)
    decimal / double Stored as a double minus its 4 lowest mantissa bits; printed %.1f or %.13g as xsd:decimal (lossy past 13 significant digits)
    point WKT POINT quantized to a 30-bit grid per coordinate, printed %f (sub-metre loss)
    dateTime A year beyond 4 digits loses its Z
    unparseable A folded-type literal QLever cannot parse loses its datatype
    spelling \uXXXX escapes, ^^xsd:string, language-tag case (same RDF term)

    Exact recreation therefore always comes from the verified raw files, never from a store.

    Joins the store enables¶

    Measured in the store and recorded in the vault (project-panatlas, 2026-09-26):

    • 3,373 of 3,377 panAtlas MeSH IRIs exist in NLM's MeSH RDF (OKN graph biobricks-mesh).
    • 3,310 panAtlas concepts reach 3,313 Wikidata entities through the OKN identifier-mappings graph.
    • 137 MeSH IRIs join the OKN graph spoke-okn only through their https variant.
    • panAtlas concepts carry no Wikidata identifiers of their own.

    Example (from web/rdf/README.md, run against the live store 2026-10-08, 1.2 s):

    PREFIX skos: <http://www.w3.org/2004/02/skos/core#>

  GRAPH <https://purl.org/okn/frink/kg/biobricks-mesh>     { ?m rdfs:label ?label } } LIMIT 3
