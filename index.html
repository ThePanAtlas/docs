    panAtlas¶

    panAtlas is a reference atlas for multi-modal evaluation across every domain of knowledge. Medicine is where its holdings run deepest today, but the atlas is not a medical atlas: each domain is mapped the same way, as a provenance-first knowledge graph that links concepts, datasets, models, their training curricula and the benchmarks that measure them. With that map, an evaluation can say where in the domain it was measured, on what and for whom, instead of reporting one context-blind number.

    It is a distributed system that runs on Cresco. Every registered dataset is managed by its own Cresco plugin running beside the data, at the site that holds it. The managers report structure, never content, up the mesh to one atlas. Shared infrastructure therefore also means shared datasets and one global understanding of them, while every dataset stays where it is, under its owner's control.

    Principles¶

    • Provenance first. Every fact says where it came from, and every number says when it was measured.
    • Describe once, evaluate many times. A dataset, model or benchmark is described once, as metadata, and every evaluation refers to that description.
    • Blanks are tracked as rigorously as facts. "We do not know what this model was trained on" is a recorded, comparable property, not a gap in a table.
    • Structure crosses the wire, content does not. Federation carries identifiers, counts, edges and hashes. Documents, images and protected data never leave their site.
    • Comparable only within one space. Embeddings are compared only within one registered (modality, model, version) space. Everything else joins through shared identifiers.

    How this documentation is kept honest

    Each page says whether something is built, measured or only designed, and dates its numbers. Where a design document and the code disagree, the page describes what the code does and marks the difference with a warning. The sources are the panAtlas repositories (ThePanAtlas/panatlas, cresco-panatlas, agent-deployment) at the commit named in the page, plus the dated project record.
